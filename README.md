# phro-project

Designer for project-specific plugins. It has no universal structure and no always-on parts: no hook, no server, no routing layer.

| Skill | Use |
|---|---|
| `design` | Before adding a capability: where it belongs, and its trigger prompts first |
| `route-test` | Whether skills really get called on real prompts, and which skill takes each miss |
| `audit` | After a plugin has grown: merge, delete and repair proposals. It never edits the plugin |

`scripts/project.py` holds the deterministic part, standard library only. It rebuilds a SQLite graph from the plugin's files on each call, so the graph cannot go stale. The graph answers structure questions such as what breaks if a part is removed; it does not route prompts.

```bash
python -I -X utf8 scripts/project.py check <plugin>
python -I -X utf8 scripts/project.py impact <plugin> <node>
python -I -X utf8 tests/test_project.py
```

`fixtures/midwork.jsonl` is a synthetic mid-task conversation that `route-test` resumes, regenerated by `fixtures/make_midwork.py`. `tests/route_cases.json` holds this plugin's own routing cases, written by its author.

Findings from `check` are candidates. On real plugins, `broken-ref` was often an example path in a skill about writing skills, and `duplicate-file` was often deliberate, so `audit` verifies each by opening the file.

Delete this plugin if two audits of real plugins produce no adopted proposal and no routing problem.
